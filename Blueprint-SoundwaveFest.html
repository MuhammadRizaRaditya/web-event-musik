1. EXECUTIVE SUMMARY

Platform ini dirancang sebagai solusi terintegrasi untuk pengelolaan, promosi, dan penjualan tiket event musik/festival berbasis Progressive Web App (PWA). Berbeda dari landing page konvensional, platform ini merupakan sistem event management end-to-end yang mencakup website publik untuk pengunjung, dashboard admin untuk penyelenggara, sistem ticketing dengan e-ticket QR Code, integrasi payment gateway Indonesia, manajemen konten (CMS), serta pelaporan penjualan dan kehadiran secara real-time.

Arsitektur: Modular Monolith dengan Next.js (frontend) + NestJS (backend) + PostgreSQL (database) + Redis (cache/queue) + Midtrans/Xendit (payment gateway).

Target: MVP live dalam 3 bulan, fitur lanjutan dalam 9 bulan.

2.2 Tujuan Pembangunan Aplikasi

  1. Menyediakan website publik event yang menarik, informatif, dan responsif.
  2. Menjual tiket secara online dengan alur checkout yang efisien dan aman.
  3. Menerbitkan e-ticket berbasis QR Code yang dapat divalidasi di venue.
  4. Mencegah overselling melalui mekanisme concurrency control di level database.
  5. Menyediakan dashboard admin untuk pengelolaan event, artis, tiket, dan konten.
  6. Menyediakan laporan penjualan, pembayaran, dan kehadiran yang akurat.
  7. Mendukung operasional check-in dengan mode offline terbatas.

3. PROBLEM STATEMENT

Bagaimana merancang platform digital terintegrasi yang mampu menjual tiket event musik secara aman, mencegah overselling dan tiket palsu, memberikan pengalaman pengguna yang premium dan cinematic, serta menyediakan dashboard operasional real-time bagi penyelenggara event?

Platform ticketing event musik yang ada seringkali terfragmentasi: penjualan tiket melalui platform pihak ketiga dengan margin tinggi, penyelenggara tidak memiliki akses langsung ke data pelanggan, pengunjung menghadapi pengalaman tidak konsisten antara website promosi dan proses pembelian tiket. Belum lagi risiko overselling, tiket palsu, dan kesulitan rekonsiliasi pembayaran.

8.6 Online Order / Checkout

Alur Checkout:

  1. Pengguna memilih kategori tiket dan jumlah
  2. Sistem validasi kuota (dengan row-level locking)
  3. Pengguna mengisi data pembeli dan pemilik tiket
  4. Sistem menghitung subtotal, biaya layanan, pajak, diskon, total
  5. Order dibuat (status: pending) dengan batas waktu pembayaran
  6. Redirect ke payment gateway
  7. Webhook verifikasi pembayaran
  8. E-ticket diterbitkan dan dikirim via email

Status Order: pending → paid → completed / expired / cancelled / refunded

8.7 Payment Management

Integrasi: Midtrans atau Xendit (API resmi).

Webhook Security:

  • Verifikasi signature HMAC menggunakan raw body (bukan parsed JSON)
  • Idempotency: setiap event ID dari gateway hanya diproses sekali
  • Verifikasi status langsung ke API gateway sebelum fulfillment
  • Unique transaction ID dengan expiry timestamp untuk mencegah replay attack

11. ARSITEKTUR SISTEM

11.1 Jenis Arsitektur: Modular Monolith

Rekomendasi: Modular Monolith untuk tahap awal dengan pemisahan domain yang jelas.

Alasan Pemilihan:

  • Tim kecil-menengah dapat mengelola satu codebase
  • Deployment lebih sederhana (satu aplikasi, satu database)
  • Domain boundaries jelas memudahkan migrasi ke microservices
  • Menghindari kompleksitas operasional microservices pada tahap awal

19. SECURITY

19.1 Authentication & Authorization

JWT dengan access token (15 menit) dan refresh token (7 hari). RBAC dengan permission-based access control. Guard di setiap endpoint API. Row-Level Security (PostgreSQL RLS) untuk isolasi data multi-tenant.

19.2 Password Hashing

Menggunakan bcrypt dengan cost factor 12. Password minimal 8 karakter, kombinasi huruf dan angka.

19.3 HTTPS

Wajib HTTPS di semua environment production. HSTS header dengan max-age 1 tahun. Redirect HTTP → HTTPS.

19.4 Input Validation

class-validator di NestJS DTO. Zod di frontend form validation. Sanitasi input untuk mencegah XSS. Validasi tipe file upload.

19.5 SQL Injection Prevention

Menggunakan Prisma ORM dengan parameterized queries. Tidak ada raw query tanpa parameter binding.

19.6 XSS Prevention

React secara default melakukan escaping. Content Security Policy (CSP) header. Sanitasi HTML jika menggunakan dangerouslySetInnerHTML.

19.7 CSRF Protection

Untuk API dengan cookie-based auth: SameSite=Strict + CSRF token. Untuk API dengan JWT di header: CSRF tidak relevan.

19.8 Rate Limiting

EndpointLimitWindow

19.9 Secure File Upload

Validasi MIME type, batas ukuran (10MB gambar, 100MB video), scan malware, simpan di object storage dengan URL tidak dapat ditebak.

19.10 Payment Webhook Signature Verification

Verifikasi HMAC signature menggunakan raw body. Bandingkan signature dengan timing-safe comparison. Tolak webhook tanpa signature valid.

19.11 Idempotency

Setiap webhook event memiliki unique event ID. Simpan di payments.idempotency_key. Jika sudah ada, return 200 tanpa memproses ulang.

19.12 Pencegahan Manipulasi Harga

Harga tiket selalu diambil dari database server. Frontend hanya kirim ticket_type_id dan quantity. Backend hitung ulang total.

19.13 Pencegahan QR Code Palsu

QR Code berisi signed JWT token dengan signature RS256. Public key tersimpan di PWA scanner. Token memiliki expiry timestamp.

19.14 Pencegahan Double Check-in

Setiap check-in dicatat di tabel ticket_checkins (append-only). Unique constraint: satu tiket satu check-in valid. Log tidak dapat dihapus.

19.15 Data Privacy

GDPR/UU PDP compliance. Data pribadi dienkripsi at rest. Akses data dibatasi berdasarkan role. Audit log untuk akses data sensitif.

19.16 Audit Logging

Semua operasi CRUD pada entitas penting dicatat. Log mencakup: user, action, entity, old/new values, IP, user agent, timestamp. Log append-only.

19.17 Backup Database

Daily automated backup (pg_dump). Simpan di object storage dengan retention 30 hari. WAL archiving untuk point-in-time recovery. Test restore berkala.

19.18 Monitoring

Sentry untuk error tracking. Grafana + Prometheus untuk metrics. Health check endpoint /health. Alerting ke Slack/Email.

19.19 Error Handling

Semua error dikembalikan dalam format JSON konsisten. Tidak mengekspos stack trace ke client. Log error di server dengan detail lengkap.

25. KESIMPULAN

Blueprint ini merancang platform event management dan ticketing berbasis PWA yang komprehensif, mencakup seluruh rantai nilai event musik - dari promosi, penjualan tiket, pembayaran, penerbitan e-ticket, hingga check-in di venue.

Poin Kunci:

  1. Arsitektur Modular Monolith dengan Next.js dan NestJS memberikan fondasi yang scalable, secure, dan maintainable.
  2. Database PostgreSQL dengan row-level locking menjamin integritas data dan mencegah overselling.
  3. Integrasi payment gateway Indonesia (Midtrans/Xendit) dengan webhook yang aman.
  4. Desain UI/UX dengan tema dark, cinematic, dan premium.
  5. PWA memungkinkan akses offline untuk halaman publik dan validasi tiket.

Dokumen ini siap dijadikan acuan dalam pengembangan, dengan roadmap bertahap yang memungkinkan peluncuran MVP dalam 3 bulan pertama, diikuti dengan fitur-fitur lanjutan pada fase berikutnya.
